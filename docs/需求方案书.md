# SVN 访达菜单需求方案书

| 项 | 内容 |
| --- | --- |
| 产品名称 | SVN 访达菜单 |
| 文档版本 | 0.1 |
| 日期 | 2026-10-16 |
| 状态 | 待确认后实现 |
| 适用系统 | macOS 12 及以上，支持 Apple 芯片和 Intel |

本文只定义本版要做的事。确认前不写代码。

## 1. 背景

付费客户端 macSVN 已从本机移除。日常仍要在访达里对已经检出的 Subversion 工作副本做两件事：更新、提交。

本版做一个很小的 macOS 工具，在访达右键菜单里提供这两项。菜单出现时不访问版本库。用户点中某一项之后，才调用本机的官方 `svn` 命令。

## 2. 目标

1. 在已登记的工作副本内，访达右键出现「SVN 更新」和「SVN 提交」。
2. 点「SVN 更新」后立即执行 `svn update`，并展示命令输出。
3. 点「SVN 提交」后先打开提交窗口；用户填写说明并确认后，才执行 `svn commit`。
4. 不扫描图标状态，不做后台轮询。

## 3. 使用者

本机已经有 Subversion 工作副本的开发者。版本库地址、账号和已保存的凭据沿用本机现有的 `svn` 配置（通常在 `~/.subversion`）。本产品不建立自己的账号系统。

## 4. 本版范围

做这些：

- 一个普通 macOS 应用，用来登记工作副本、检查 `svn` 是否可用、显示提交窗口和结果窗口。
- 一个访达扩展，只负责右键菜单。
- 两个动作：更新、提交。
- 操作结果的展示、取消正在运行的命令、本地操作记录。

不做这些：

- 图标徽章、访达工具栏按钮、边栏菜单。
- 检出、添加、还原、对比、日志、分支、合并、切换地址、锁定、冲突解决、版本库浏览。
- 定时或在后台执行 `svn status`、`svn update`、`svn commit`。
- 自带一份 Subversion，或自己实现 SVN 协议。
- Windows、Linux。
- 登录、许可、付费。

移除登记目录时，只从本产品的列表里去掉，不删除磁盘上的工作副本，不修改项目文件。

## 5. 总体方案

系统分成三块。

```
访达右键
   │
   ▼
访达扩展                只判断菜单是否显示，并把选中路径交给主应用
   │  用户点击某一项
   ▼
主应用                  提交窗口、结果窗口、登记列表
   │  此时才启动进程
   ▼
本机 svn 可执行文件     访问版本库
```

访达扩展由系统在需要显示菜单时启动。扩展不执行 `svn`。主应用收到点击后再启动 `svn` 进程。主应用平时不必一直开着；收到点击时由系统打开它。

登记列表放在 App Group 共享目录，主应用和扩展都读这份列表。扩展启动时把这些目录设为自己负责的目录。主应用每次保存列表后通知扩展刷新。这样菜单只出现在用户登记过的工作副本里面。

`svn` 的参数用参数数组传递，不拼进 shell 命令，避免路径和提交说明被当成命令。

应用不放进 Mac App Store，也不使用沙盒。这样可以对用户登记的任意工作副本调用本机 `svn`。本机开发签名即可运行。

## 6. 使用前的准备

主应用第一次打开时显示设置窗口。之后从启动台或「应用程序」再次打开，也是这个窗口。窗口里有三块内容。

**svn 命令**

按下面的顺序找可执行文件，找到第一个能运行且 `svn --version` 成功的路径：

1. 用户在设置里指定的路径
2. `/opt/homebrew/bin/svn`
3. `/usr/local/bin/svn`
4. `/opt/local/bin/svn`

界面写明当前用的是哪一个路径。找不到时，说明需要先安装官方客户端，并给出「选择 svn 可执行文件」。不在图形界面的默认 `PATH` 里碰运气，因为从访达启动的程序通常只有 `/usr/bin:/bin:/usr/sbin:/sbin`，而现在的 macOS 已经不在 `/usr/bin/svn` 提供命令。

**工作副本**

- 「添加」打开系统选文件夹面板。
- 选中的文件夹自身有 `.svn`，就把该文件夹记为工作副本根目录。
- 自身没有、某个上级目录有 `.svn`，就把那个含 `.svn` 的上级目录记为根目录，并在界面写明实际登记的路径。
- 向上直到用户主目录仍找不到 `.svn`，不登记，并说明这不是工作副本。
- 列表支持移除。移除后扩展不再为该目录提供菜单。
- 同一根目录不重复登记。

这里的判断只看有没有 `.svn` 目录，不运行 `svn`。

**访达扩展**

窗口用一段固定说明告诉用户打开：

系统设置 → 通用 → 登录项与扩展 → 访达扩展 → 打开「SVN 访达菜单」。

另有一个按钮「重新启动访达」。点击后执行 `killall Finder`。这是访达扩展更换负责目录后，菜单没有马上出现时的补救，不自动执行。

## 7. 右键菜单

### 7.1 什么时候出现

同时满足才显示菜单：

- 右键目标位于某个已登记的工作副本根目录之内（包含根目录本身）。
- 右键的是选中的文件或文件夹，或是文件夹窗口的空白处。
- 空白处右键时，目标是当前打开的这个文件夹。

菜单固定两项，顺序不变：

1. SVN 更新
2. SVN 提交

不在已登记工作副本里时，不显示这两项，也不插入禁用项。

侧栏和工具栏不提供菜单。

### 7.2 点下去之前允许做什么

准备菜单时，扩展只做本地判断：这条路径是不是落在已登记根目录里。允许读取登记列表。

准备菜单时禁止：

- 启动 `svn`
- 连接版本库
- 执行 `svn status`
- 为了画徽章而遍历文件
- 定时重复上述动作

`.svn` 只在「添加工作副本」时查找。弹出右键菜单时不再为每个文件向上搜索磁盘。

### 7.3 点下去之后做什么

扩展把动作名称和全部目标路径交给主应用，然后结束自己的工作。

主应用先做这些检查，任一失败就打开结果窗口，不启动 `svn`：

| 情况 | 窗口里的说明 |
| --- | --- |
| 找不到可用的 `svn` | 写明设置窗口里如何指定路径 |
| 没有目标路径 | 没有可操作的文件 |
| 目标不属于同一个已登记工作副本 | 一次只能操作同一个工作副本 |
| 这个工作副本已有命令在运行 | 已有操作正在进行 |

同一时间整个应用只运行一个 `svn` 进程。

## 8. SVN 更新

用户点「SVN 更新」后，不需要第二次确认，直接执行。

命令：

```text
svn update --non-interactive -- <目标路径...>
```

目标路径就是右键时的那些路径：

- 选中文件夹：更新这个文件夹。
- 选中文件：更新这些文件。
- 文件夹空白处：更新当前文件夹。
- 多个路径：放在同一次 `svn update` 里。

结果窗口在命令启动时就打开，标题为「正在更新」，正文随输出增长。命令结束后：

- 退出码为 0：标题改为「更新完成」。
- 退出码不是 0：标题改为「更新失败」，正文保留标准输出和标准错误。
- 用户取消：标题改为「更新已取消」，并结束 `svn` 进程。

本版不解析冲突，不提供解决界面。冲突文件以 `svn` 自己打印的文字为准。

同时发一条系统通知，内容与窗口标题一致。点击通知把结果窗口带到前面。

## 9. SVN 提交

### 9.1 打开窗口

用户点「SVN 提交」后，主应用先执行：

```text
svn status --xml --non-interactive -- <目标路径...>
```

这一步属于这次点击，不是后台刷新。状态命令只覆盖选中的目标。选中文件夹时，使用 `svn status` 的默认深度，列出该文件夹下面的改动。

状态命令失败时，不打开可提交的窗口，直接显示结果窗口「无法获取改动」，正文为命令输出。

状态命令成功后打开「提交到 SVN」窗口。

### 9.2 窗口内容

说明文字：将提交勾选的改动。未纳入版本控制的文件不会提交。

列表两列：状态、路径。状态用下面的中文，并保留 `svn` 的原始字母供核对。

| svn 状态 | 界面文字 | 默认 |
| --- | --- | --- |
| modified | 修改 | 勾选，可取消 |
| added | 新增 | 勾选，可取消 |
| deleted | 删除 | 勾选，可取消 |
| replaced | 替换 | 勾选，可取消 |
| unversioned | 未纳入版本控制 | 不勾选，不能勾选 |
| missing | 文件缺失 | 不勾选，不能勾选 |
| conflicted | 冲突 | 不勾选，不能勾选 |
| 其他 | 显示原始状态名 | 不勾选，不能勾选 |

没有「修改 / 新增 / 删除 / 替换」任何一项时，列表仍显示查询结果，提交按钮不可用，旁边说明「没有可提交的改动」。

提交说明是多行文本，必填。去掉首尾空白后长度为 0，提交按钮不可用。

按钮：

- 「提交」：执行提交。
- 「取消」：关闭窗口，不执行 `svn commit`。

用户可以取消勾选部分文件。最终命令只包含仍被勾选的路径。某个文件被取消后，不改用它的父目录作为目标，避免把没勾选的文件一起提交。

### 9.3 执行提交

```text
svn commit --non-interactive -m <提交说明> -- <勾选的路径...>
```

提交说明作为单独参数，保留用户输入的换行。

结果窗口规则与更新相同，标题分别是「正在提交」「提交完成」「提交失败」「提交已取消」。完成后发系统通知。

本版不执行 `svn add`。未纳入版本控制的文件留在列表里只作提示。

## 10. 认证与网络

所有 `svn` 命令都带 `--non-interactive`。

不增加「信任服务器证书」之类的参数。证书或账号被拒绝时，结果窗口原文展示 `svn` 的错误，并附上固定说明：请先在终端对这个版本库成功操作一次，让 Subversion 记住凭据；本版本不保管密码。

密码、用户名、证书内容不写入操作记录，不写入界面日志，不放进命令的调试输出。

## 11. 结果窗口与操作记录

结果窗口使用等宽字体，文字可选中复制。窗口保持在普通应用窗口层，打开时置于最前。按钮为「关闭」。进行中的窗口另有「取消」，取消会结束对应的 `svn` 进程及其子进程。

操作记录保存在 App Group 目录的 `operations.log`，只保留最近 200 条。每条包含：时间、动作（更新、提交或获取状态）、退出码、目标路径、输出的前后各 20 行。不记录提交说明以外的秘密；提交说明可以记录，因为它是用户准备写进版本库的文字。密码没有收集入口，因此也不会被记录。

设置窗口提供「打开操作记录」。

## 12. 数据

登记信息是一份 JSON：

```json
{
  "svnBinary": "/opt/homebrew/bin/svn",
  "workingCopies": [
    "/Users/me/projects/demo"
  ]
}
```

`svnBinary` 为空字符串时，使用第 6 节的自动查找顺序。`workingCopies` 保存绝对路径，按添加顺序显示。

本产品不修改 `~/.subversion`，不修改工作副本里的文件内容。`svn update` 和 `svn commit` 本身对工作副本的正常改动，按 Subversion 的默认行为发生。

## 13. 非功能要求

- 菜单弹出不做版本库访问，本地判断应在右键的当次交互里完成。
- 路径含空格、中文或符号时，与普通路径一样能更新和提交。
- 从访达启动、从启动台启动，都能找到 Homebrew 安装的 `svn`。
- 命令输出使用用户当前语言环境，不强制改成英文。
- 更新或提交进行中关闭结果窗口，命令继续运行；再次从通知打开，仍能看到同一次输出。用户要停止时使用「取消」。

## 14. 验收

验收机安装官方 `svn`，并用 `svnadmin create` 建一个本地 `file://` 版本库，检出两份工作副本 A 和 B。另准备一个普通文件夹 C，里面没有 `.svn`。

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| AC-01 | 未登记任何目录时，在 A 里右键 | 没有「SVN 更新」「SVN 提交」 |
| AC-02 | 登记 A 的根目录后，在 A 的子文件上右键 | 出现上述两项 |
| AC-03 | 在 C 里右键 | 没有上述两项 |
| AC-04 | 登记前后抓取进程与网络 | 弹出菜单期间没有 `svn` 进程，也没有连到版本库 |
| AC-05 | 对 A 里一个有远端新提交的子文件夹点「SVN 更新」 | 只更新这个子文件夹，窗口显示 `svn update` 的输出 |
| AC-06 | 修改 A 中一个文件，右键该文件并提交一段中文说明 | 版本库中该次提交的说明与输入一致，且只包含这个文件 |
| AC-07 | 提交窗口里取消勾选其中一个已修改文件 | 被取消的文件没有进入版本库 |
| AC-08 | 提交说明只输入空格 | 「提交」按钮不可用，没有 `svn commit` 进程 |
| AC-09 | 选中一个未 `svn add` 的新文件再点提交 | 列表标明未纳入版本控制，不能勾选，没有 `svn add` |
| AC-10 | 同时选中 A 和 B 的文件后点更新 | 不执行，提示一次只能操作同一个工作副本 |
| AC-11 | 更新进行中再次点更新 | 第二次不启动新的 `svn`，提示已有操作正在进行 |
| AC-12 | 更新进行中点取消 | `svn` 进程结束，窗口标题为「更新已取消」 |
| AC-13 | 把 `svn` 可执行文件路径改成一个不存在的路径后再更新 | 不启动命令，提示重新指定 `svn` |
| AC-14 | 路径中含空格和中文的文件做一次更新和一次提交 | 两次都作用在该文件上 |
| AC-15 | 从设置中移除 A | A 的右键菜单消失；A 的文件仍在磁盘上，工作副本仍可用 |
| AC-16 | 版本库需要登录且本机没有已保存凭据 | 命令失败，窗口展示 `svn` 的认证错误，本产品不弹出密码框 |

AC-04 是「点下去才执行」的验收项。菜单显示、登记目录、查找 `.svn` 都不算执行 SVN 操作。

## 15. 风险

- 访达扩展要用户在系统设置里手动打开一次。未打开时，主应用的设置窗口仍可用，但右键没有菜单。
- 系统升级后，访达扩展可能需要重新打开或重新启动访达。设置窗口保留「重新启动访达」。
- 图形程序看不到终端里的 `PATH`。本方案用固定安装位置和用户手动选择来避免这个问题。
- `--non-interactive` 遇到要交互的认证会失败。本版把失败原文展示给用户，不在菜单流程里询问密码。
- 超大工作副本上对根目录做状态查询会等待较久。提交窗口在查询完成前显示「正在读取改动」，并可以取消。查询范围限于本次右键的目标，不扩大到其他登记目录。

## 16. 实现时的模块划分

确认本方案后再写代码。建议按下面四块拆开，便于对照验收：

1. 登记与 `svn` 路径：对应第 6 节和 AC-13、AC-15。
2. 访达扩展菜单：对应第 7 节和 AC-01 至 AC-04。
3. 更新与结果窗口：对应第 8、11 节和 AC-05、AC-10 至 AC-12、AC-14。
4. 提交窗口：对应第 9 节和 AC-06 至 AC-09、AC-16。

四块都完成并且第 14 节全部通过，本版即完成。
